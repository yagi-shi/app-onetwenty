要件定義書はエラー処理を網羅的には規定していない。明示されているのは、完了済み習慣のタップでエラーを出さないこと（FR-4.2）、文字数超過のハード拒否（FR-1.5.1）、通知拒否時の表示（FR-5.8.3）、Live Activity・通知が使えない場合の代替（FR-2.14.1 / FR-5.6）である。それ以外は本書の方針（EH-00）に従って設計する。

## 1. 方針

### EH-00 エラー表示の原則

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | FR-4.2 / FR-3.6 / NFR-2 / TR-4（横断） |
| 設計     | ①**ユーザー自身の明示的な操作が失敗し、ユーザーに取れる行動がある場合だけ表示する**（例：習慣の登録が保存できなかった）②OS 連携（通知・Live Activity・サウンド）の失敗は**表示しない**。代替手段が要件で定められており（FR-2.14.1 / FR-5.6）、次のアクティブ化で自動的にやり直される ③仕様どおりの挙動はエラーとして扱わない（完了済みのタップ、上限による「＋」の非表示、通知の拒否）④エラー表示にも警告色・煽る文言を使わない（システム標準のアラートのみ）⑤ログは端末内（`os.Logger`）にのみ残し、外部へ送らない（TR-4 / NFR-3） |
| 理由     | 原則4（長く滞在させない）と FR-3.6（煽らない）の精神に合わせ、ユーザーが対処できないエラーで画面を止めない |
| 代替案   | **すべての失敗をアラートで知らせる**：通知の予約失敗のように次回自動で直るものまで表示すると、操作のたびに意味のない確認を強いるため却下 |

## 2. 個別の設計

### EH-01 永続化ストアを開けない

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | 横断（03 DM-01 / DM-12） |
| 発生条件 | 起動時の `ModelContainer` 生成が失敗する（空き容量不足、ストアの破損、スキーマ移行の失敗） |
| 表示     | ホームの代わりに全画面で「データを読み込めませんでした。iPhoneの空き容量を確認して、もう一度お試しください」と「もう一度試す」ボタン |
| 復旧     | ボタンで `AppEnvironment.retryContainer()` を呼ぶ（04 MD-51）。成功したら残りの依存を組み立て、`AppCoordinator` を生成し、ルート判定（オンボーディング／ホーム）に進めてから 01 AR-04 の(1)〜(4) を実行する。**このときの最初のアクティブ化は `.cold` として扱う**（04 MD-50）。失敗したらこの画面に留まる |
| ルートの扱い | この状態は **`AppEnvironment` の `rootState = .storeUnavailable`** で表す（04 MD-51）。`AppCoordinator` はサービス群をイニシャライザで受け取るため、ストアを開けない間は生成しない。エラー画面を出す主体は `AppEnvironment` を見るルートビューであり、オンボーディング・ホームのどちらにも進まない |
| しないこと | **ストアを自動で削除・作り直さない**（履歴を失わせない。要件 §6「履歴を失わせない」） |
| 理由     | 起動できない状態で黙って空のデータを見せると、履歴が消えたように見えるため |

### EH-02 操作の保存に失敗

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | FR-1.9 / FR-6.3 / FR-6.4（`HabitService`。04 MD-41） |
| 発生条件 | `HabitRepository` の書き込みが例外を投げる |
| 表示     | 「保存できませんでした。もう一度お試しください」のアラート（OK のみ） |
| 復旧     | **登録・名前変更**：ウィザードは閉じず、最後のステップ（2分確認）に留まる。入力と分解状態は保持したまま、同じ操作をやり直せる（FR-1.10.1 の破棄はキャンセル時の規定であり、失敗時には適用しない）。**並び替え**：画面上の並びを元に戻す。**アーカイブ**：一覧は変えない |
| 副作用の扱い | 保存に失敗した場合、リマインダーの同期・通知許可の要求は行わない（保存が成功した場合のみ実行する） |

### EH-02b 完了記録の保存に失敗

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | FR-2.15 / FR-3.1（04 MD-40 / MD-11、03 DM-05） |
| 発生条件 | `SessionRepository.insertIfAbsent` が例外を投げる |
| 表示     | **表示しない**。タイマー画面は通常どおり完了表示にする |
| 復旧     | 失敗した実行を**保存待ち（`onetwenty.pending.completions`）へ移し、実行中マーカーは消す**（03 DM-10）。次の4つの契機で `SessionService.flushPendingCompletion()` を呼び、同じ `sessionID` で保存をやり直す。保存は冪等なので重複しない（03 DM-05）。**1件以上の保存に成功したら `ReminderService.sync()` を呼ぶ**（保存待ちの解消で当日全完了になった場合に、当日分のリマインダーを外すため。FR-5.4 / TR-5。04 MD-40） |
| 再試行の契機 | ①**保存に失敗した直後**、同じ処理の中で1回だけやり直す ②**タイマー画面を閉じてホームへ戻る時点**（`AppCoordinator` が完了表示の終了の通知を受けたとき。04 MD-50）③**`SessionService.start` の冒頭** ④**シーンのアクティブ化時**（`recoverOnActivation` の手順⑤。04 MD-40）。①②で成功すれば、ホームに戻った時点で完了表示になる。**いずれの契機でも、成功したらリマインダーの同期を伴う**（上記） |
| 二重実行の防止 | その習慣・その日の保存待ちが残っている場合、`start` は `alreadyCompletedToday` として拒否する。保存に失敗しただけで実際には2分を走り切っているため、同じ日にもう一度実行させない（FR-4.2） |
| 他の習慣への影響 | **保存待ちは実行中マーカーとは別に持つため、他の習慣の `start` を妨げない**（FR-4.1 の1日3件が止まらない）。保存待ちが複数溜まる状態も許容する |
| 最終手段 | ①〜④がいずれも失敗した場合は保存待ちに残り、次のアクティブ化で再び試みられる。**`startedAt` から24時間を過ぎた保存待ちは `recoverOnActivation` の手順⑤で破棄する**（04 MD-40。FR-2.15.1 と同じ基準） |
| 理由     | ユーザーは2分を走り切っており、対処できることがない。一方、アクティブ化だけを契機にすると、**タイマー画面からホームへ戻るだけでは復旧せず、完了したはずの習慣が未完了のまま表示され、もう一度実行できてしまう**。画面を閉じる時点と開始時点にも再試行を置くことでこれを防ぐ |

### EH-03 通知の予約・取消に失敗

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | TR-5 / FR-2.13 / FR-5.7（04 MD-42 / MD-22） |
| 発生条件 | `NotificationClient.add` が例外を投げる（保留上限の超過等） |
| 表示     | なし |
| 復旧     | **リマインダー**：`sync()` は差分方式なので、次の `sync()`（アクティブ化時等）で足りない日が再び追加される。**完了通知（`timer.`）**：再予約はしない。Live Activity が終了の見た目で伝え（FR-2.11.2）、アプリに戻れば完了が表示される |

### EH-04 Live Activity を開始できない

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | FR-2.11 / FR-2.14.1 / FR-5.6（04 MD-44） |
| 発生条件 | ユーザーが iOS の設定でこのアプリの Live Activity を無効にしている、または開始要求が失敗する |
| 表示     | なし |
| 復旧     | タイマーはそのまま動作する（計測は `startedAt` との差分。TR-1）。裏での完了は通知（FR-2.13）で伝わる。通知も拒否されている場合は、アプリに戻った時点で完了表示される（仮定 A-11） |

### EH-05 サウンドを再生できない

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | FR-2.7 / FR-2.7.1（04 MD-45） |
| 発生条件 | 音声ファイルの読み込み失敗、`AVAudioSession` の設定失敗 |
| 表示     | なし |
| 復旧     | ハプティクスは同じ呼び出しの中で独立して鳴らす（片方の失敗でもう片方を止めない）。完了文言も通常どおり表示する |

### EH-06 同梱データを読み込めない

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | NFR-6.1 / FR-1.5.1.1 / FR-1.6 / FR-2.9（04 MD-46、03 DM-11） |
| 発生条件 | JSON ファイルの欠落・形式不正（リリース前のテストで防ぐべき実装上の誤り） |
| 表示     | なし。デバッグビルドでは `assertionFailure` で停止させる |
| 実行時の代替 | **テンプレート**：空として扱い、テンプレート提示を出さない（2分確認から進み、汎用パターンは再分解ステップで常に選べる）。**検出語**：空として扱い、検出しない（ハード拒否の文字数制限は動く）。**完了文言**：String Catalog の既定の一言を1つ使う |
| 予防     | `ContentLoader` のテスト（04 MD-46）で、日英の全ファイルが読み込めることと件数・内容の制約を検証する |

### EH-07 入力の文字数超過・空入力

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | FR-1.4.1 / FR-1.4.2 / FR-1.5.1 / FR-6.4.2.1（04 MD-13、02 SC-40） |
| 表示     | ダイアログは出さない。入力欄の下の「文字数 / 上限」を常時表示し、超過中は超過していることが分かる表示にして送信操作を無効にする。空入力（空白のみ）も送信操作を無効にする |
| 復旧     | 入力を直せば即座に送信可能になる。同じステップに留まり、それまでの入力は失わない |
| 備考     | これがアプリ唯一のハード拒否である（FR-1.5.1）。頻度副詞・目標表現の検出は拒否ではなく、代替案の提示または再分解への誘導（02 SC-42） |

### EH-08 登録上限に達している

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | FR-1.9（04 MD-21 / MD-41） |
| 通常の経路 | アクティブ3件のときは「＋」を表示しない（02 SC-20）ため、ウィザードを開けない。エラーではない |
| 例外の経路 | ウィザードを開いている間に何らかの理由でアクティブが3件になった状態で登録した場合、`HabitService.register` が `limitReached` を返す |
| 表示     | 「登録できるのは3件までです」のアラート。OK でウィザードを閉じ、起動元へ戻る（`WizardViewModel` は `limitReached` として終了を `AppCoordinator` に通知し、`presentedWizard` を `nil` にするのは `AppCoordinator`。04 MD-50 / MD-55） |

### EH-09 実行中マーカーの不整合

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | FR-2.15 / FR-2.15.1（04 MD-11 / MD-33） |
| 発生条件と扱い | ①**保存値が壊れている**（JSON として読めない）：マーカーなしとして扱い、キーを削除する。残存 Live Activity は `sessionID` が一致しないため掃除される ②**対象の習慣が存在しない、またはアーカイブ済み**：`recoverOnActivation` で「破棄」として扱い、Session を保存しない（03 DM-08 の不変条件を守る） |
| 表示     | なし |
| 要件上の既知の挙動 | 端末のメモリ解放でプロセスが終了し、120秒未満で戻った場合も、強制終了と区別できないため記録は破棄される（FR-2.15。要件注記で受け入れ済み）。Live Activity はそれまでカウントを続けているが、エラーとしては扱わない |

### EH-10 端末時刻の変更

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | TR-1 / FR-3.10 / FR-3.12 / FR-4.4（04 MD-10 / MD-02、03 DM-06） |
| 時刻を巻き戻した | 現在時刻が `startedAt` より前になった場合、経過は0として扱う（`TimerEngine`）。タイマーは `startedAt` に戻るまで0秒のまま進まない |
| 時刻を進めた | 経過が120秒以上になり、完了として扱われる。経過時間を `startedAt` との差分で算出する方式（TR-1）の性質上避けられない。要件 §1 の「既知の抜け穴」と同じく、2分待たずに記録する手段になりうるが、端末の時刻設定の変更を要するため受け入れる |
| タイムゾーンを変えた | 日付キーは常にその時点のタイムゾーンで計算し直す（03 DM-06 / 仮定 A-23）。過去の Session の日付が移り、連続日数やヒートマップが変わることがある。**これは FR-3.12（過去の記録が後から変化しない）の唯一の例外として要件に明記されている**（要件 v1.20。日付を保存しない FR-3.10 の帰結） |
| 表示     | いずれも表示しない |

### EH-11 通知許可が拒否されている

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | FR-5.6 / FR-5.8.3 / FR-5.8.4 / FR-2.14.1 |
| 扱い     | エラーではなく状態として扱う。設定画面で通知の項目を無効表示にし、案内の一文と設定アプリを開くボタンを出す（02 SC-61）。他の機能は制限しない（FR-5.6） |
| 復旧     | ユーザーが iOS の設定で許可すると、次のアクティブ化で許可状態を取得し直し、リマインダーを予約する（FR-5.8.4。04 MD-50） |

### EH-12 設定アプリを開けない

| 項目     | 内容 |
| -------- | ---- |
| 対応要件 | FR-5.8.3 |
| 扱い     | `open` が失敗しても何も表示しない。案内の一文（「iOSの設定で通知を許可してください」）が残っているため、ユーザーは手動で設定アプリを開ける |

### EH-13 完了済み習慣のタップ

| 項目     | 内容 |
| -------- | ---- |

## 3. リトライ方針のまとめ

| 対象 | 方式 | 契機 | 上限 |
| ---- | ---- | ---- | ---- |
| ストアの生成（EH-01） | 手動 | 「もう一度試す」ボタン | なし |
| 習慣の操作（EH-02） | 手動 | ユーザーが同じ操作をやり直す | なし |
| 完了の記録（EH-02b） | 自動 | ①保存失敗の直後 ②タイマー画面を閉じる時点 ③次の `start` の冒頭 ④次のアクティブ化 | `startedAt` から24時間（FR-2.15.1 と同じ基準で破棄） |
| リマインダーの予約（EH-03） | 自動 | 次の `sync()` | なし（差分方式のため重複しない） |
| 完了通知・Live Activity・サウンド（EH-03〜05） | しない | — | — |
| 通知許可の状態（EH-11） | 自動 | 毎回のアクティブ化 | なし |
