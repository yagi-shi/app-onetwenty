# 目的

要件定義書と設計書をもとに、機能ごとにチケットファイルを作成してください。

各チケットファイルでは、その機能の実装Todoも管理します。

# 入力

* 対象範囲: $ARGUMENTS
  * 空の場合は、全機能を対象とする
* 参照する情報源（存在するものをすべて確認する）
  * `docs/design/06_task_breakdown.md`（存在する場合は、これを最優先の元資料とする）
  * `docs/design/` 配下のその他の設計書
  * `docs/requirements/requirements.md`
* 既存のチケット
  * `docs/tickets/` 配下

# 基本方針

* 作成するのはチケットファイルのみ。実装コードは書かない
* 要件定義書・設計書にない機能のチケットを作らない
* 要件定義書と設計書が食い違う場合は、要件定義書を優先し、該当チケットの「備考」に記載する
* 既存のチケットは上書き・削除しない
  * 既存チケットと内容が重複する場合は、新規作成せずに報告する

# チケットとTodoの粒度

* チケット: 1機能 = 1チケット
* Todo: チケット内の実装タスク（半日〜1日程度）
  * `06_task_breakdown.md` がある場合は、そのタスクを対応する機能のチケットにTodoとして振り分ける
  * ない場合は、設計書と要件定義書から同じ粒度でTodoを作る
* 1つのチケットにTodoが10個を超える場合は、機能をさらに分割できないか検討する

# 出力

## 保存先とファイル名

* 保存先: `docs/tickets/`
* ファイル名: `{3桁の連番}_{機能名の英語スネークケース}.md`
  * 例: `001_project_setup.md`、`002_habit_data_model.md`、`003_habit_registration.md`
* 連番は依存関係順（先に実装すべきものが小さい番号）に振る
* 既存チケットがある場合は、最大の番号の続きから振る
* 上記以外のファイルは作成・変更しない

## チケットの書式

```markdown
# {連番} {機能名}

## 概要
{この機能で実現すること（2〜3行）}

## 対応要件ID
- FR-x.x
- NFR-x.x

## 参照する設計書
- docs/design/xx_xxx.md（該当セクション）

## 依存チケット
- {連番} {機能名}（なければ「なし」）

## 完了条件
- {チケット全体として満たすべき条件}

## Todo
- [ ] {タスク}
  - 完了条件: {実装が完了し、対象の単体テストが通ること など}
- [ ] {タスク}
  - 完了条件: {…}

## 備考
{食い違い・仮定・注意点。なければ「なし」}
```

## Todoの管理ルール

* Todoは、Markdownのチェックボックス（`- [ ]`）で管理する
* 実装が完了したTodoは `- [x]` に更新する
* 実装中に追加で必要になったTodoは、同じチケットの「Todo」に追記する
* チケットの全Todoが `- [x]` になり、完了条件を満たしたらチケット完了とする

# セルフチェック

作成後、以下を確認する。

* 対象範囲のすべての機能に、チケットがあるか
* `06_task_breakdown.md` がある場合、すべてのタスクがいずれかのチケットのTodoに含まれているか
* 連番が依存関係順になっているか（依存先のほうが小さい番号か）
* 依存チケットに、存在しない番号を書いていないか
* 各Todoに完了条件があるか
* 既存チケットを上書きしていないか

# 完了報告

すべてのチケットの作成が終わったら、以下の形式で報告する。

```
Todoの作成が完了しました。

作成したチケット:
- 001_xxx.md（Todo x件）
- 002_xxx.md（Todo x件）

未解決事項:
- {あれば記載。なければ「なし」}
```
