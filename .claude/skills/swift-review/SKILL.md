# Swift コードレビュー基準

**必須で確認すべき項目のみ**をレビューする。可読性や保守性の細かい改善提案は行わず、リリースブロッカーとなる問題のみを対象とする。対象プロジェクトはUIKitベース。

## 出力形式

必ず総合スコアから始める。

```
*総合スコア: NN / 100*
（1〜2行で全体評価）
```

その後に Critical / High の順で指摘を並べる。該当がない見出しは出さない。指摘が1件もない場合はその旨を明記する。

### スコア基準

- Critical が1件以上ある: 60点未満
- High のみ: 60〜85点（件数に応じて配分）
- 指摘なし: 90点以上

### 優先度の定義

- **Critical**: クラッシュ、情報漏洩、審査リジェクトのいずれかに直結する。マージ不可
- **High**: 上記に至る蓋然性はあるが条件付き。マージ前に対応すべき

この2段階に収まらない指摘は出さない。

## レビューの方針

以下の3つの観点**のみ**をチェックする。

1. Swift文法として問題ないか（コンパイル・実行時エラーのリスク）
2. セキュリティリスクがないか（訴訟・情報漏洩のリスク）
3. ストアリリース基準を満たしているか（Apple審査のリスク）

レビュー対象外：
- コードスタイル（インデント、命名規則など）
- パフォーマンス最適化（致命的でない限り）
- アーキテクチャの改善提案
- テストコードの追加提案
- リファクタリング提案

## 1. Swift文法チェック

必須確認項目：

- **強制アンラップ（`!`）の誤用**
  - クラッシュリスクがある `!` の使用（特にオプショナルチェーン以外）
  - IBOutlet以外での強制アンラップ
- **メモリリーク**
  - クロージャ内での `self` の強参照（`[weak self]` または `[unowned self]` の欠如）
  - Delegate/Notificationの解放漏れ
- **実行時エラーのリスク**
  - 配列の範囲外アクセスの可能性
  - 強制キャスト（`as!`）の不適切な使用
  - ゼロ除算の可能性

### 並行処理（Swift 6 strict concurrency）

- `@MainActor` の付与漏れ。UI更新を行う型・メソッドに付いているか
- `Sendable` 未準拠の型をアクター境界を越えて渡していないか
- `@unchecked Sendable` の使用。安全性の根拠がコメント等で示されているか
- `nonisolated(unsafe)` の使用。回避手段がないケースに限られているか
- GCDとasync/awaitの混在。`DispatchQueue.main.async` で済ませている箇所が `@MainActor` に置き換えられないか
- `Task { }` 内での self の扱い。意図しない延命が起きていないか

対象外：
- オプショナルバインディングの書き方（`if let` vs `guard let`）
- アクセス修飾子の最適化（動作に影響しない場合）
- 非推奨APIの使用（代替が明確で動作する場合）

## 2. セキュリティチェック

必須確認項目：

- **個人情報の取り扱い**
  - ユーザーデータの暗号化なしでの保存（UserDefaults、ファイルシステム等）
  - 生体認証データの不適切な取り扱い
- **通信セキュリティ**
  - HTTPSではなくHTTPでの通信（ATS違反）
  - 証明書検証の無効化
  - APIキー・トークンのハードコード
- **データ漏洩リスク**
  - クリップボードへの機密情報コピー
  - スクリーンショットに機密情報が含まれる可能性
  - バックグラウンド時のスクリーンキャプチャ対策なし
- **認証・認可**
  - トークンの安全でない保存（KeyChain未使用）
  - セッション管理の欠如
  - 権限チェックの不備

### ログ出力

- `print()` による個人情報・トークンの出力
- `OSLog` / `Logger` の privacy 指定漏れ。文字列補間はデフォルトで `.private` だが、`String` 以外の型や明示的な `.public` 指定で意図せず露出する場合がある
- 個人情報を含む変数には `\(value, privacy: .private)` が指定されているか
- リリースビルドに残るデバッグログ

対象外：
- コードの難読化（リバースエンジニアリング対策）
- ログレベルの最適化（機密情報が含まれていない場合）

## 3. ストアリリース基準チェック

必須確認項目：

- **プライバシー関連**
  - 位置情報・カメラ・マイク等の権限リクエストに `Info.plist` の説明文（`NSxxxUsageDescription`）がない
  - ATT（App Tracking Transparency）の実装漏れ（トラッキングする場合）
  - `PrivacyInfo.xcprivacy` の記載漏れ。Required Reason API（`UserDefaults`、`FileManager` のファイル日時取得、`systemUptime` 等）を使用しているのに理由コードが宣言されていない場合はリジェクト対象
  - サードパーティSDK追加時、そのSDKのプライバシーマニフェストと署名の有無
- **App Store Review Guidelines違反**
  - 未成年向けアプリでの広告ID使用
  - ギャンブル・アダルトコンテンツの不適切な実装
  - アプリ内購入のガイドライン違反（価格表示等）
- **UIデザイン要件**
  - Safe Areaの無視によるノッチ領域への侵入
  - Dynamic Typeへの未対応（アクセシビリティ）
  - ダークモード対応の欠如（色のハードコード）
- **パフォーマンス**
  - メインスレッドでの重い処理（フリーズの原因）
  - 大量のメモリ消費によるクラッシュリスク

対象外：
- デザインの美しさ
- アニメーションの滑らかさ（動作する場合）
- ローカライゼーションの完全性（最低限英語対応があれば可）

## 出力例

良い例：

```
*総合スコア: 55 / 100*
強制アンラップによるクラッシュリスクとATS違反があり、このままではマージ不可。

### Critical
- `UserListView.swift:45` 強制アンラップによるクラッシュリスク
  `let user = users[indexPath.row]!` → 配列範囲外の可能性

### High
- `APIClient.swift:78` HTTPSではなくHTTPでの通信（ATS違反）
  `http://api.example.com` → `https://api.example.com`
```

避けるべき指摘：

```
- 変数名が不明瞭（`a` → `accountBalance`）
- メソッドが長すぎる（100行 → 50行以下に分割推奨）
- コメントが不足している
```

## 補足

差分に含まれない箇所は対象外とする。確信度の低い指摘は出さない。
